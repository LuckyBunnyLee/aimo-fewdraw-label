## Checks and judgments

- **Selection: pass, with population limit.** Independent computation verifies the roster really is in SHA256(202610210935|id) order. The builder verifies that reached originals are exactly its first 2,474; independently replays the fixed SHA256(20261025|id) top-320 selection. It uses reached status but no earlier strict tag, binary eligibility, answer yield or success threshold for sampling. Tags are attached afterward: R 124, NR 41, UNUSABLE 153, FLOOR 2. Using the reached pool is defensible for inference to that pool; it does not establish unconditional representativeness of unreached problems because reaching was time-limited. Do not generalize to the entire roster or benchmark.
- **Pairing: pass.** Independently checked 19,200 problem/wave/replicate cells, each with five families; base/sham text bytes and system prompts match. All 96,000 identities and seeds are distinct; seeds follow the frozen 63-bit identity rule and no identity overlaps fresh6h. Real/sham family blocks are shuffled within each shared wave. Four draws per family remain contiguous; this is randomized block order, not request-level interleaving.
- **Primary: pass.** All 320 originals enter the all-answer mean(sham_a,sham_b) minus mean(gs,dlm); non-correct and nonnumeric draws count as unsolved. Original bootstrap is 2,000 resamples with fixed seed. Calibration CAL1 and CAL2 precede the directional reading. Loss, gain, unresolved, calibration failure, and fewer-than-eight-waves/not-measured are specified. Identical endpoint labels are not proof of independence: the calibration is a diagnostic, not an independence certificate.
- **Secondaries/eligibility: pass for exploratory reporting, with edge-case fix 4.** The scorer implements T1 joint >=3, T2 own >=3, T3 own >=1, T4 sham-minus-N0, base contrast/tau, eligibility displays and earlier-UNUSABLE stratification. Three binary waves is a defensible frozen compromise; eligibility is outcome-dependent, so these remain conditional secondary populations. FLOOR joins the non-UNUSABLE S1 group and is explicitly named binary_or_floor by code.
- **Power: conditional planning pass.** Exact replay gives true mean 0.04422794, power 1.000 at both 12 and 8 waves in 2,000 simulations, half-widths 0.01256494 / 0.01315098, and null either-direction resolution 0.053 / 0.048. Approximate MDE is 0.01796. These are normal-CI simulations using READY63 rates; they do not simulate passing CAL1/CAL2, the scorer's bootstrap, or all possible fresh-pool heterogeneity. They support planning, not guaranteed power of the complete calibrated decision rule.
- **Cost: estimate passes; cap implementation fails.** 76,800 requests x 1,000 tokens / 1,375 tokens/s / 3,600 = 15.515 GPU-h, about 76.8M output tokens before replacements and loading. Three replacements could consume the remaining budget; caps can legitimately leave fewer than 12 or eight waves. See fixes 1–2.
- **Pre-emption: conditional pass.** PAUSE takes effect at a wave boundary; STOP_NOW abandons a wave, and fresh identities from at most three replacement waves take its place. All started identities are excluded from future blocks, including killed blocks after sealing. This preserves within-wave pairing and avoids duplicate submission. Ordinary pause latency of about 80 minutes is an estimate, not a service guarantee; urgent STOP_NOW is the usable CVPR pre-emption route. These controls do not inspect correctness, but token/time censoring can correlate with difficulty; do not call abandonment statistically independent of outcomes.
- **Endpoint: sampling/environment match with binding gap.** Resource reserve, affinity, cgroup, offline variables, no-think template check, bf16, sampling settings, prefix caching and LLM arguments match the reference in substance (max_active moves from admission to pinned manifest). New rendering uses the text/tokenize route the reference explicitly cross-checked. Runtime parity cannot be certified on CPU. The new runner omits the reference MODEL-BINDING/ENGINE-CONFIG evidence and trusts an arbitrary admitted model_path.
- **Sealed TEST:** no reviewed builder/scorer/run-core path opens a sealed TEST split; this verifier did not open or modify it. The source is the pinned existing fresh6h roster, not a new TEST draw. The supplied roster metadata does not itself prove historical disjointness from sealed TEST; that historical provenance remains unverified here. No new split access is justified to resolve it.

## Ranked fixes

1. **Required, CPU code/control fix: make 20 GPU-h real.** `wave_runner.py` constructs the tokenizer/model/LLM before `run_block` starts its timer, contradicting the amendment's explicit inclusion of loading. `run_block` never checks GPU hours inside a wave. Independent fake-clock replay finishes a nominally 20-hour-capped run with `reason=complete` and 21.0 recorded hours. Start accounting before initialization, enforce the hard in-wave hour limit, and include all blocks/load failures. Add a meaningful CPU cap-overrun replay. Log/re-freeze before generation.
2. **Required, CPU code/control fix: conservative killed-block and token accounting.** `seal()` sums terminal record tokens and uses last terminal-file mtime for elapsed; it loses all active prefixes and time after the last terminal record. Thus repeated deaths/resumes can exceed both caps. Persist cumulative counters or charge a conservative bound through process termination; refuse resume if cost cannot be bounded. The normal in-wave token check uses `>` before stepping, permitting overshoot at equality and one additional engine step; reserve remaining active capacity or otherwise enforce the stated hard 90M cap. Preserve abandoned work and identities.
3. **Required, admission binding fix: bind actual endpoint and required code.** Reintroduce recorded config/tokenizer/engine binding and independently validate the admitted model against revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`, with max_model_len=8192 and capture_sizes=[1,2,4,8,16,32]. Same template does not establish same weights. Require exactly the three named code hashes: the current loop accepts an empty code_sha256 mapping. Bind those hashes to the reviewed freeze, not merely a self-consistent new admission file. CPU validation plus CL's required GPU preflight should precede launch; V23 has not launched it.
4. **Required for a reading for every outcome, CPU scorer edge fix:** freeze explicit undefined-secondary readings. `tagset` computes nanquantile of all-NaN bootstrap ratios when mean real NR is zero; JSON can then contain NaN without a defined interpretation. Return null plus an explicit undefined-denominator reading, with no numeric CI. Explicitly label no eligible originals and all-zero-variance CAL2 cases as not estimable (the latter currently conservatively fails calibration). Include synthetic zero-denominator/no-eligible/all-perfect cases before re-freezing. Keep all secondaries descriptive and T4 empty-CI distinct from evidence against calibration.
5. **Wording/provenance, no GPU:** report power as conditional on READY63 simulation and distinguish resolution power from calibrated-rule power. Correct the ready note's assertion that the builder itself verifies roster hash order: it only verifies a prefix; V23 checked hash order separately. Preserve TEST exclusion via existing approved split provenance or metadata without opening sealed contents.

One-line read-back: Outcome-blind selection and same-wave identical-text controls replay correctly, but hard-cap accounting, admission binding and undefined-secondary readings need correction before GPU admission.
